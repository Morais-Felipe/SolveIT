<objective>
Criar a aplicação web `solveit-web` conectada à API, com identidade visual da referência e autenticação completa.
</objective>

<stack>
- **Vite + React 19 + TypeScript**, a partir do template oficial `react-ts` (versões fixadas pelo template; TypeScript na versão que ele indicar).
- **Tailwind CSS v4** com o plugin `@tailwindcss/vite` e `@import "tailwindcss"` (sem `tailwind.config.js` de v3).
- **shadcn/ui** inicializado pelo CLI oficial; componentes copiados para `src/components/ui/` somente quando usados.
- **React Router** em modo declarativo (`BrowserRouter` + `Routes`).
- **Axios**: uma única instância em `src/lib/api.ts`.
- **Vitest + React Testing Library + user-event + jsdom** para testes de componente.
</stack>

<decisions-for-approval>
- **D-1 Onde guardar o token (recomendado: `localStorage`).** Necessário para "restaurar a sessão válida" ao recarregar a página (WEB-01). Ao abrir o app, o token salvo é validado com `GET /api/auth/me`; se a API recusar, é apagado. Risco conhecido: um script malicioso injetado na página poderia lê-lo (XSS). Mitigação: o React escapa conteúdo por padrão, o projeto não usa `dangerouslySetInnerHTML`, e o token vale só 1 h. Alternativas: só em memória (perde a sessão a cada recarga, não atende WEB-01) ou cookie `httpOnly` (mais seguro, mas exige mudar a autenticação do back-end — fica para v2).
- **D-2 Comunicação com a API em desenvolvimento (recomendado: proxy do Vite).** O Vite repassa `/api/*` para `http://localhost:8080`. O navegador enxerga uma única origem, então não é preciso abrir CORS no back-end agora.
- **D-3 Estrutura (recomendado):** pasta `solveit-web/` na raiz, irmã de `solveit-api/`.
</decisions-for-approval>

<design>
- `src/lib/api.ts`: instância Axios com `baseURL: "/api"`; interceptor de requisição adiciona `Authorization: Bearer`; interceptor de resposta converte Problem Details em um erro com `code`, `detail` e `errors` por campo; resposta 401 encerra a sessão.
- `src/lib/types.ts`: tipos espelhando os DTOs usados (`Usuario`, `Perfil`, `TokenResponse`, `ProblemDetail`).
- `src/auth/AuthContext.tsx`: estado `carregando | anonimo | autenticado`, funções `entrar`, `cadastrar` (cadastra e entra), `sair`; restauração via `/auth/me` ao iniciar.
- `src/routes/`: `RotaProtegida` (redireciona para `/login`) e `RotaPorPerfil` (esconde telas que o perfil não usa; a API continua sendo a autoridade).
- Telas: `/login`, `/cadastro` e um layout autenticado com barra lateral cujos itens dependem do perfil, apontando para páginas provisórias das próximas fases.
- Tema: modo escuro com destaque laranja via variáveis CSS do shadcn/ui, seguindo `docs/design/SOLVEIT-UI-REFERENCE.md`.
</design>
