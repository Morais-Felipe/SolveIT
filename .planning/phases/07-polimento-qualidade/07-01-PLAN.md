Quem clona o repositório sobe API, front-end, MySQL e um SMTP falso com um comando, e qualquer erro inesperado da API vira uma resposta 500 padronizada, sem stack trace, SQL, segredo ou nome de entidade.

<context>

- `ApiErrorCode.INTERNAL_ERROR` e `RESOURCE_NOT_FOUND` já existem; o 403 é produzido pelo `RestAccessDeniedHandler` da cadeia de segurança.
- O CI (critério 6) já existe desde o PR #25; este plano não mexe nele.
- O README já usa o Mailpit como SMTP falso em `docker run` avulso.
</context>

<risk>
Um `@ExceptionHandler(Exception.class)` captura tudo o que sai do controller, inclusive:
- `AccessDeniedException` lançada por `@PreAuthorize` e pelos services → viraria **500 em vez de 403**;
- `ResponseStatusException(NOT_FOUND)` dos services → viraria 500 em vez de 404;
- `HttpRequestMethodNotSupportedException`, `NoResourceFoundException` → 405/404 virariam 500.
O handler precisa devolver essas exceções ao mecanismo certo, e cada caso tem teste.
</risk>

<decisions-for-approval>
- **D-1 Handler genérico com exceções preservadas (recomendado):** `@ExceptionHandler(Exception.class)` que (a) relança `AccessDeniedException` e `AuthenticationException` para a cadeia de segurança responder 403/401 como hoje; (b) para exceções que já carregam um status HTTP (`ErrorResponse`, como `ResponseStatusException`, 404 e 405 do Spring), responde com esse status no formato do SolveIT (`RESOURCE_NOT_FOUND` para 404); (c) para o resto, 500 `INTERNAL_ERROR` com a mensagem fixa "Ocorreu um erro inesperado. Tente novamente." e o erro completo apenas no log.
- **D-2 Identificador do erro (recomendado):** a resposta 500 traz `errorId` (UUID curto) que também aparece na linha de log. Quem relata o problema informa o id; quem investiga acha o stack trace no log. Não revela nada interno.
- **D-3 Front-end servido por nginx no compose (recomendado):** o build de produção do Vite vira arquivos estáticos num container nginx, que também repassa `/api` para a API. Mesma origem no navegador, sem CORS, igual ao proxy do Vite em desenvolvimento. Alternativa: rodar `vite dev` em container, descartada por não representar a entrega.
- **D-4 Serviços e portas:** `mysql` (8.4.x fixo), `mailpit`, `api`, `web`. Só `web` (8080 → app) e a interface do Mailpit (8025) ficam expostos, e apenas em `127.0.0.1`. MySQL e API ficam na rede interna do compose. `api` espera o MySQL ficar saudável (healthcheck) antes de subir.
- **D-5 Segredos por `.env`:** `.env.example` versionado com nomes e instruções; `.env` real no `.gitignore`. Sem valor padrão para `SOLVEIT_JWT_SECRET` e senhas: o compose falha com mensagem clara se faltarem. O README mostra como gerar o segredo.
- **D-6 Sem atalho para o primeiro ADMIN:** o compose não cria administrador, mantendo a política de `docs/PRIMEIRO-ADMIN.md`. O README mostra como executar aquele procedimento contra o MySQL do compose com `docker compose exec`.
- **D-7 Imagens:** API em `eclipse-temurin:17` (build com o Maven Wrapper, execução só com JRE, usuário não root); web em `node:22` para o build e `nginx` estável para servir. Versões fixadas por tag de patch.
</decisions-for-approval>
