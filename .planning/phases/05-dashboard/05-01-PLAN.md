<objective>
Dar a administradores e atendentes uma visão operacional confiável, autorizada e calculada no banco.

Output: `GET /api/dashboard/resumo` (ADMIN e ATENDENTE; SOLICITANTE 403).
</objective>

<contract>
```json
{
  "totais": { "aberto": 0, "emAndamento": 0, "resolvido": 0, "criticaAberta": 0 },
  "porCategoria": [ { "categoriaId": 1, "nome": "Rede", "quantidade": 0 } ],
  "cargaPorAtendente": [ { "atendenteId": 2, "nome": "João", "emAndamento": 0 } ],
  "abertosPorPrioridade": { "BAIXA": 0, "MEDIA": 0, "ALTA": 0, "CRITICA": 0 }
}
```
- Listas ordenadas: `porCategoria` por quantidade desc, nome; `cargaPorAtendente` por quantidade desc, nome. Só aparecem itens com quantidade > 0.
- `abertosPorPrioridade` sempre traz as quatro prioridades, inclusive zeradas.
</contract>

<decisions-for-approval>
- **D-1 Escopo (recomendado):** os agregados usam exatamente `ChamadoSpecifications.visivelPara(usuario)`. ADMIN vê o todo; ATENDENTE vê a fila (ABERTO sem responsável) e os chamados atribuídos a ele. É o que permite o critério 3 (reconciliar com a lista) e resolve a pendência "escopo dos agregados para atendentes" do STATE.
- **D-2 Carga ativa (recomendado):** quantidade de chamados `EM_ANDAMENTO` por atendente responsável. RESOLVIDO já saiu do trabalho do atendente.
- **D-3 "CRITICA aberta" (recomendado):** status `ABERTO` e prioridade `CRITICA`, ou seja, críticos ainda esperando alguém assumir. Reconcilia com `GET /api/chamados?status=ABERTO&prioridade=CRITICA`.
- **D-4 Por categoria (recomendado):** todos os chamados no escopo, de qualquer status, agrupados por categoria (inclui categorias inativas que ainda tenham chamados).
</decisions-for-approval>

<design>
- `DashboardRepository` (componente com `EntityManager`) monta consultas com a Criteria API reaproveitando o predicado de `ChamadoSpecifications.visivelPara(usuario)`: contagens por status, por prioridade (com status ABERTO), por categoria e por atendente (com status EM_ANDAMENTO), cada uma com `COUNT` + `GROUP BY` executado no MySQL.
- `DashboardService` (`@Transactional(readOnly = true)`) relê o usuário, exige ADMIN ou ATENDENTE (defesa em profundidade além do `@PreAuthorize`) e monta o DTO.
- Uma consulta por agrupamento (4 consultas no total), sem carregar entidades `Chamado`.
</design>
